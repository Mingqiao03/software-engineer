# 方法 2：文档与现有流程分析（采集中）

> **状态：待收集材料。** 本文件目前只有框架，材料到手后逐条填入，**没有材料的部分留空并标注"未获得"**。
> ⚠️ 不得编造文档内容、截图或规则。拿不到就如实写"无法获得"，并说明这对结论的限制。

## 一、为什么用这个方法

访谈回答的是"用户怎么感受"，文档与流程分析回答的是"**规则实际怎么写的、流程实际怎么跑的**"。
两者互补：访谈里说"有短任务优先"，到底是不是、阈值多少、谁设的，要靠文档或配置来核实。

对本案具体要回答四个问题：

1. 现存机制（Slurm）**已经覆盖**了哪些能力，避免重复建设；
2. 现存机制的**实际规则参数**是什么（分区、优先级、时限、配额）；
3. 历史上**做过什么、为什么废弃**（旧预约表、旧登记表）；
4. **成文规则与真实行为**的差距在哪里（这正是需求所在）。

## 三、分析框架

每份材料按同一结构记录，避免只做"资料摘抄"：

### DOC-xx：《材料名称》

- **来源与获取方式**：谁提供、什么时候、原始形式（截图/导出/文档）
- **覆盖范围**：能回答什么、不能回答什么
- **关键事实**（逐条，可核对）：
  1. …
  2. …
- **与访谈的对照**：
  - 印证了哪条（例：INT-03 说"已有短任务优先" → DOC-01 显示确实存在，阈值为 …）
  - 推翻了哪条
  - 访谈提到但文档里没有的（= 潜规则 / 未成文规则）
  - 文档里有但访谈没人提的（= 规则不可见 / 没人知道）
- **引出的需求或问题**：CAND-xx

## 五、限制说明（写进报告）

- 文档反映的是**写下来的规则**，不等于实际执行；
- 群公告等非正式文本可能不完整、有历史遗留；
- 拿不到 DOC-06 时，**量化结论只能来自原型阶段的模拟数据**，且必须明确标注为模拟；
- 材料由管理员提供时，需在报告中说明**提供者角色**（不写姓名），以及是否存在选择性提供。
