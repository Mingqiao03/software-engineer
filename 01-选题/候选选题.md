# 候选选题（用于 W5 决策）

**已知约束**（来自本人的回答）：

- 干系人来源：清华校内师生与教务 + 实验室与科研协作（校外企业/开发者社区**不可达**）
- 方向偏好：生成式 AI / 智能体；科研 / 开发者工具
- 组队：2–3 人
- 硬约束：必须能拿出**真实需求获取证据**（否则 74 分上限、伪造访谈一票否决）

**筛选原则**：从"能拿到证据"倒推，而不是从"想做什么"正推。

## 评估口径

每个候选按四条打分，前三条是细则的直接映射：

| 口径 | 对应细则 | 说明 |
|---|---|---|
| 复杂度 ≥3 项 | 项目价值与复杂度 10 分 | 9 项清单见 README |
| 两个原型可"真正不同" | 两原型设计质量 15 分；只有 1 个有效原型 → 69 分上限 | 差异须在方案/设计假设层面 |
| 干系人可达且冲突真实 | 干系人分析与需求获取 12 分 | 无真实获取 → 74 分上限 |
| 评估可量化 | 评估方案与证据 10 分 | 评估须有任务、指标、基线 |

## 候选 A：组会/科研进度协作的 AI 助手

**场景**：研究生每周要写周报、准备组会汇报；导师要掌握真实进度；新进学生要查历史。
现状是周报流于形式、导师看不到真实进展、学生觉得写周报是负担。

**干系人**：研究生（写）、导师（看）、实验室管理员/秘书（归档）、新进学生（检索历史）

**主要冲突**：**进度透明度 vs 学生隐私与自主**——导师想看到真实卡点，学生倾向报喜不报忧。

**复杂度满足**：多目标干系人 ✓ / 需求冲突与价值权衡 ✓ / 涉及生成式 AI ✓ / 需求不确定且持续变化 ✓（≥3）

**两个原型（差异维度＝自动化程度 + 人机职责分配）**：

- P1 结构化模板 + 人工填写：规则驱动，无生成，强调可控与低幻觉
- P2 智能体自动生成：AI 从 commit/笔记/论文自动起草进展，人只审核与修订

**需求获取方案（≥2，均可达）**：
访谈研究生与导师各 ≥3 人 / 组内问卷 / 历史周报与组会纪要文档分析 / 竞品（飞书周报、Notion 模板）

**风险**：涉及个人进度数据，需处理**隐私与伦理**；"周报工具"有被认定为"普通工具"的风险，
必须靠"透明度 vs 隐私的权衡建模"把需求难点做出来。

## 候选 B：AI 辅助文献综述工具（**推荐**）

**场景**：研究生做综述要读几十上百篇论文，抽取、去重、构建研究脉络，
并且**最怕引用是编的**。现有 AI 工具（如各类 chat 式助手）恰好在这里不可信。

**干系人**：研究生（做综述）、导师（审脉络质量）、学科馆员（资源与检索规范）、
课程助教/期刊审稿视角（对引用规范的要求）

**主要冲突**：**效率 vs 可信性**——AI 起草快，但引用真实性无法保证；
覆盖度 vs 精确度；自动化程度 vs 可追溯性。**领域知识复杂**（检索式、纳入排除标准）。

**复杂度满足**：涉及生成式 AI ✓ / 复杂业务规则与领域知识 ✓ / 多目标干系人 ✓ /
质量需求（可信性、可追溯性）✓ / 多系统外部接口（文献库 API）✓（远超 3 项）

**两个原型（差异维度＝规则 vs AI，细则明列的差异维度）**：

- P1 **规则 + 引文网络**：纯检索与硬索引，无生成，所有条目可回溯到原文
- P2 **智能体 + 生成**：LLM 抽取与综述草稿，每句必须挂可核验引用，配人工接管与拒答机制

**需求获取方案（≥2，均可达）**：
深度访谈"写过综述/正在写综述"的研究生 ≥5 人 / 问卷（组内 + 同方向同学）/
文档分析（已有综述、目标期刊的投稿要求、课程对引用规范的要求）/ 竞品分析（Zotero、各类 AI 综述工具）/ 日志（本人或同学的文献库使用情况）

**为什么推荐**：

1. **把红线变成得分点**。细则明确要求：用 AI 就要评估"错误、幻觉、偏见、隐私、拒答、人工接管"。
   本课题的**核心需求难点正好就是幻觉与引用核验**——不是要绕开的坑，而是课题的立意本身。
   这直接命中外包评分维度里最难写的那几项。
2. **证据好拿**。访谈对象就在身边（组内 + 同届），且这类人有真实痛点、愿意聊。
3. **两个原型天然不同且都是真需求**。P1/P2 分辨"人的职责分配"与"规则 vs AI"，
   不是加页面、不是修 bug，禁得起"两原型只是同一方案不同版本"的质疑。
4. **可量化评估**。指标可定义为：检索召回率、引用可核验比例（对/错）、
   人工修订耗时、综述覆盖度——有基线（纯人工 Zotero 流程）可比。

**风险与对策**：

- 领域偏窄是优点也是风险：干系人若全来自同组，会被质疑代表性。
  → 对策：至少跨 2–3 个课题组抽样。
- 若访谈到的痛点不够"冲突"，需在干系人之间挖出真实分歧（如导师要广覆盖、学生要快出稿）。

## 候选 C：实验数据与可复现性的合规管理

**场景**：实验室实验流程、数据处理、可复现性。导师要可复现，学生要快。

**干系人**：硕博生、导师、实验室安全员/合规、外部合作者

**主要冲突**：严谨（可复现/合规）vs 效率

**复杂度满足**：安全/合规 ✓ / 多干系人 ✓ / 复杂业务规则 ✓ / 需求冲突 ✓

**两个原型（差异维度＝集中式 vs 本地优先）**：
P1 集中式平台统一管理；P2 本地优先 + 按需共享，隐私与合规权衡不同

**为什么排在后面**：

1. 与本人"想要生成式 AI"的偏好匹配度低。
2. **最大的坑在证据可达性**：实验数据与合规记录常涉密受保护，
   访谈对象（安全员/合规）不像研究生那样容易约到。
3. 数据敏感度会带来伦理审查负担，时间成本高。

**适用条件**：若实验室本身有明确的合规整改需求、且能找到愿意访谈的管理方，则可翻盘。
